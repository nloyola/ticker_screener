# AGENTS: Working in this Repository

This guide is for human and AI coding agents contributing to the ticker screener. It summarizes the stack, safe edit areas, required tooling, and the commands you should run before merging a branch.


## Project Overview

- Stack: Python 3.12 (`.python-version`), uv (`pyproject.toml`, `uv.lock`), stdlib `sqlite3`, pandas, scipy and statsmodels for BreakoutIQ's statistics, scikit-learn for its gradient-boosted trees, `ta` for the indicators, `requests` for the Tiingo and EODHD REST APIs, openpyxl for the `import` spreadsheet.
- Data: the SQLite database named by `DB_NAME`, shared with the Go dashboard in [nloyola/stock_analyzer](https://github.com/nloyola/stock_analyzer), where this repo is the `screener/` submodule. The screener owns `schema.sql` and fills `ticker`, `price_data`, `benchmark_price`, `stock_criteria` and `metadata`, and `company_name`, each ticker's company name, `screened_session`, the sessions each market was scored on, `signal`, the append-only archive of every confirmed breakout, with the near-misses, watchlist sessions and continuations kept beside them, each marked with its `kind`, and the signal tracking tables, `signal_price` (each signal's own price path), `signal_outcome` (its outcome per horizon) and `signal_track` (its frozen path, breakout failure and retest), and `backfill_run`, each `backfill-history` run's coverage and biases, and `analysis_run` with `analysis_result`, BreakoutIQ's analysis runs and their findings, none of which is market data, so all of them survive `db-init`. The dashboard's admin pages own the contents of `sector` and `subsector`; `import` still replaces both from a spreadsheet. The dashboard's own tables (`admin_user`, `admin_session`, `analyzer_schema_migration` and the rest of its migrations' tables) live in the same file: never read, write, drop or empty them, and never add them to `schema.sql`, with one exception: `analyze` and the backfills read `issuer` and `issuer_listing`, the issuers grouping the listings of one company, to archive only each issuer's primary listing (`app/repositories/issuer_repo.py`), and treat them missing as no issuers; and a fetch and `analyze` read each ticker's state in `security_master`, the dashboard's security master, and leave out a ticker flagged for review or inactive there, neither requesting nor scoring it, its stored rows kept (`app/repositories/security_state_repo.py`), treating the table missing as no ticker held, and `analyze` and the backfills read each ticker's exchange there, which a bare US ticker's archived records carry. Only `clear_market_data` (`app/db.py`) empties tables, and only those in `MARKET_DATA_TABLES`.
- Structure: see [CLAUDE.md § Architecture](CLAUDE.md#architecture).
- Deployment: the `ticker-screener` image (`Dockerfile`, with `.dockerignore` as an allow-list), built and shipped by the parent repo's `make release:build` and `make release:push`, and run by hand on `tikitak-vps` in one-off containers (`docker compose -f compose.production.yaml run --rm screener analyze`). The runbook is the parent's `documentation/install.md`.


## Safe Areas To Edit

- Do edit: `app/**`, `tests/**`, `main.py`, `schema.sql`, `config/**`, `pyproject.toml`, `Dockerfile`, `.dockerignore`, `README.md`.
- Change with care:
  - `schema.sql` - the parent's tests use a verbatim copy (`internal/repo/testdata/screener_schema.sql`, checked by its `make schema:check`), and the dashboard's repositories read these tables. A schema change needs the matching change in the parent. `schema.sql` only creates missing tables, and only `db-init` runs it, so a change to an existing table also needs an upgrade appended to `UPGRADES` in `app/db.py`, leaving an old table exactly as `schema.sql` now creates it, and so does a new table, which the upgrade creates; never edit an upgrade that has shipped.
  - `uv.lock` - change it only through `uv add`, `uv remove` or `uv lock`, never by hand.
- Avoid editing (local data or build output, all gitignored):
  - `.venv/`, `__pycache__/`, `.mypy_cache/`, `.ruff_cache/`
  - `data/`, `/*.json`, `/*.xlsx`


## Environment & Tooling

- Tools: `uv` and `ruff` (on the `PATH` via Nix; `uv run ruff` also works from the dev group). `uv sync` creates `.venv` from `uv.lock`.
- Environment file: `.env` at the root, read by `load_config` (`app/config.py`) after the environment and any `.env` piped on stdin (read only when the environment lacks a key the command needs), filling only keys they leave unset, so a `PRICE_API` set only here applies even when the environment holds every key. Keys: `DB_NAME` (the database path, needed by every command), `PRICE_API` (the price API `ticker-fetcher` and `run-refresh` fetch from: `tiingo`, the default, or `eodhd`), `TIINGO_API_KEY` (needed by `ticker-sync`, and by `ticker-fetcher` and `run-refresh` when `PRICE_API` is `tiingo`) `EODHD_API_KEY` (needed by `ticker-fetcher` and `run-refresh` when `PRICE_API` is `eodhd`) and `HISTORY_DATABASE_FILE` (the price history database, needed by `history-fetch`, which also needs `PRICE_API` and its key, and by `backfill-history`). A command missing a key it needs, or given an unknown `PRICE_API`, exits 2 with one line naming it. Never commit it, and never print it - list key names only (`grep -oE '^[A-Za-z_][A-Za-z0-9_]*=' .env`).
- `main.py` runs from any directory: it finds `config/0-stdout.json` and `schema.sql` relative to its own files.


## Coding Standards

**[CODING_STANDARDS.md](CODING_STANDARDS.md)** holds the rules code is held to: Python style, the layering, the database and its upgrades, rule and payload versions, logging and secrets, and testing. Read it before writing code, and check changes against it in review.

- `uv run ruff check .` and `uv run ruff format --check .` clean (`pyproject.toml`: 120 columns, single quotes, rules `E`, `F`, `I`, `UP`, `B`).
- Keep the layering: commands parse arguments and call a service or worker class; repositories own all SQL; `models.py` has no I/O. A new table gets a repository in `app/repositories/`, registered in `build_container` (`app/wiring.py`).
- A new subcommand subclasses `BaseCommand` in `app/commands/`, lists the config keys it needs in `REQUIRED_CONFIG`, takes its workers from the container in `handle` (never in `__init__`), and is registered in `main()`.
- Log through `logging.getLogger(__name__)`; `print` only a command's own summary or prompt.
- Repositories open every connection through `connect(db_path)` (`app/db.py`), never their own; it commits on success, rolls back on error and closes. Work spanning several statements outside a repository goes inside `SQLite.connect()`, which wraps it in one transaction.


## Screener version

`SCREENER_VERSION` (`app/analyzer.py`) names the rules a score was produced by, and `rule_settings()` beside it is the snapshot of their settings that travels with it. Bump the version (semver) in the same commit as any change to what `analyze` scores:

- Major: a core condition or status rule added, removed or redefined, so a breakout or status means something different.
- Minor: a secondary indicator added, removed or redefined, or a threshold or window changed (`VOLUME_RATIO_MIN`, `RSI_BAND`, `SMA_RISING_DAYS` and the like), which moves results without changing what they mean.
- Patch: a fix that changes some results without changing any rule's intent, such as an off-by-one in a lookback or the handling of missing rows.

A change that leaves every score as it was (logging, refactoring, the fetch) needs no bump. A new threshold or window is a module-level constant in `app/analyzer.py`, never an inline number, and is listed in `rule_settings()`: `tests/test_rule_settings.py` fails on a constant that is neither listed there nor named in its `NOT_RULE_SETTINGS`.

## Pre-Merge Checklist

Feature branches use the `dev-*` prefix and merge into `main`. Before merging:

- `uv run ruff check .` and `uv run ruff format --check .` are clean.
- `uv run pytest` passes.
- The changed commands run against a scratch database.
- Docs updated (`README.md`, this file, `CLAUDE.md`) when behavior or commands change.
- No `.env`, database or other gitignored files committed.
- After merging, commit the new submodule commit in the parent repo, with any matching schema snapshot change.


## Security & Secrets

- Never commit `.env`, databases or spreadsheets.
- Never log or print `TIINGO_API_KEY` or `EODHD_API_KEY`. `app/redaction.py` is the guard: `redact()` masks both keys' values and any `api_token=` value, the `stdout` handler's filter (`config/0-stdout.json`) applies it to every log record, tracebacks included, and `main.py`'s `sys.excepthook` applies it to a crash's traceback. Keep new output going through logging, and run any message holding a URL or an error through `error_detail()` or `redact()`.
